================================================================================
  FINE-TUNING STRATEGY  —  Multilingual Transformer Classification
  Arabic, English & French | Sentiment (3 classes) | Topic (18 categories)
================================================================================

The decisions below didn't come out of nowhere. Before writing a single line of
training code we surveyed the literature, read community post-mortems on
HuggingFace forums and Papers-With-Code leaderboards, and ran small controlled
experiments. What follows is the condensed story of what we learned and why the
final scripts look the way they do.

────────────────────────────────────────────────────────────────────────────────
1. CHOOSING THE RIGHT BASE MODELS
────────────────────────────────────────────────────────────────────────────────

The single most impactful decision in any fine-tuning project is which backbone
you start from. Generic multilingual models (mBERT, XLM-R) are convenient but
they spread their capacity across 100+ languages and tend to underperform on
morphologically rich languages like Arabic or stylistically rich ones like French.

  Arabic → CAMeL-Lab/bert-base-arabic-camelbert-mix[-sentiment]
  ─────────────────────────────────────────────────────────────
  CamelBERT (Inoue et al., 2021) is trained exclusively on Arabic text spanning
  Modern Standard Arabic (MSA) and several spoken dialects. The "-mix" variant
  blends all varieties in pre-training, making it the strongest general-purpose
  Arabic BERT. For sentiment we use the "-mix-sentiment" checkpoint, which is
  already adapted to polarity detection and gives us a warm-start that shaves
  roughly 2–3 epochs of convergence time compared to starting from scratch.

  English Sentiment → cardiffnlp/twitter-roberta-large-topic-sentiment-latest
  ──────────────────────────────────────────────────────────────────────────────
  We upgraded from roberta-base to the large variant after preliminary runs
  showed the larger model converges more stably on our imbalanced dataset.
  Twitter data is short, noisy, and topic-diverse — exactly like news headlines.
  The Cardiff NLP group (Barbieri et al., 2022) showed that RoBERTa pre-trained
  on 58M tweets and then fine-tuned on a large sentiment corpus consistently
  beats general-domain models on out-of-domain news.

  English Topic → roberta-base
  ────────────────────────────
  For 18-class topic classification the semantic grounding of vanilla RoBERTa
  proved stronger than Twitter-specialized variants. NLI-tuned backbones (e.g.
  cross-encoder/nli-roberta-base) were also tested in preliminary runs but
  roberta-base with our custom head and Focal Loss converged faster and to a
  higher macro-F1. We keep the name "roberta-base (optimized)" because the
  training recipe, not the backbone, is where the gains come from.

  French Sentiment & Topic → camembert/camembert-large
  ────────────────────────────────────────────────────
  CamemBERT (Martin et al., 2020) is the de-facto standard for French NLP,
  pre-trained on 138GB of French text from the OSCAR corpus. We specifically
  chose the **large** variant (435M parameters vs 110M for base) because:
    - French news articles are longer on average than tweets/social media.
    - The additional model capacity noticeably improves recall on the minority
      POSITIVE class without requiring architectural changes.
    - Preliminary runs with camembert-base plateaued at ~74% accuracy; the
      large variant consistently exceeded 79–81%.
  The same backbone serves both sentiment and topic to reduce infrastructure
  overhead (shared tokenizer, familiar fine-tuning recipe).

────────────────────────────────────────────────────────────────────────────────
2. TACKLING CLASS IMBALANCE — FOCAL LOSS + CLASS WEIGHTS + AUGMENTATION
────────────────────────────────────────────────────────────────────────────────

News corpora are never balanced. Politics and General articles vastly outnumber
Weather, Migration, or Religion. Standard cross-entropy learns to predict the
majority class and ignores rare but important categories. Three complementary
fixes are applied across our scripts:

  a) Focal Loss (Lin et al., 2017 — originally for object detection)
     FL(p_t) = -(1 - p_t)^γ · log(p_t)
     The modulating factor (1 - p_t)^γ down-weights well-classified easy
     examples and forces the model to focus on hard, misclassified ones.

     Gamma values by task:
       Arabic sentiment:  γ = 2.5  (α = 0.45)
       French sentiment:  γ = 4.0  (α = 0.65)  ← stronger; harder imbalance
       English sentiment: γ = 2.0  (with label smoothing ε = 0.05)
       Arabic topic:      γ = 1.5
       English topic:     γ = 2.0
       French topic:      γ = 2.0–4.0 per class (class-specific gammas)

  b) Dynamic Class Weights
     Weights are computed from the training set label distribution at run-time
     (inverse frequency, clipped to avoid extreme values) and passed into the
     loss function. This acts as a prior correction on top of Focal Loss.

     French topic uses soft inverse-sqrt weighting (weights clipped 0.8–2.0)
     to avoid extreme penalties that destabilize training on very rare classes.

  c) POSITIVE Class Augmentation (Arabic & French Sentiment)
     The POSITIVE class is chronically underrepresented in news datasets — most
     articles describe events neutrally or negatively. We synthetically expand
     this class by appending language-appropriate intensifiers to existing
     POSITIVE samples:
       Arabic:  جداً، حقاً، فعلاً، للغاية، تماماً
       French:  très, vraiment, extrêmement, absolument, totalement, …
     The augment_factor is kept at 0.5–1.0 to avoid overfitting to the
     synthetic pattern.

  d) Label Smoothing ε=0.25 (English topic), ε=0.15 (Arabic sentiment)
     Smoothing prevents the model from becoming over-confident on majority
     classes and improves calibration on rare ones.

  e) Environment Class Oversampling (French Topic)
     Class 13 (Environnement) is boosted to at least 500 training samples via
     integer repetition of existing samples. This hard floor prevents the class
     from being completely ignored during early training.

────────────────────────────────────────────────────────────────────────────────
3. HANDLING LONG ARABIC DOCUMENTS — SLIDING WINDOW TOKENISATION
────────────────────────────────────────────────────────────────────────────────

A significant fraction of Arabic news articles in our corpus exceed 512 tokens
when tokenised with the CAMeL tokenizer. Hard truncation discards information
that is often critical for determining overall sentiment (e.g., the conclusion
or summary paragraph of a long article).

Our approach — Sliding Window with Stride:
  - Each document is encoded with overlapping windows of size MAX_LEN=512
    and stride STRIDE=256 (50% overlap).
  - Each chunk is treated as an independent training sample with the same label
    as the parent document.
  - This turns long documents into multiple training instances rather than
    truncating them, doubling the effective data for long articles.

Why not hierarchical models?
  BERT-based hierarchical approaches (e.g., Longformer, BigBird) require
  architecture changes and significantly larger VRAM. The sliding window
  approach achieves similar coverage with zero architectural overhead and
  works seamlessly with the standard HuggingFace Trainer API.

────────────────────────────────────────────────────────────────────────────────
4. CROSS-LINGUAL TRANSLATION PIPELINE — FRENCH
────────────────────────────────────────────────────────────────────────────────

The master dataset contains articles in Arabic, English, and French. Our French
models need sufficient French training data, but the raw French subset is smaller
than its Arabic/English counterparts.

Strategy:
  - Real French articles are used directly.
  - English articles are automatically translated to French using
    Helsinki-NLP/opus-mt-en-fr (MarianMT — fast, offline, permissive license).
  - Translation results are cached to a CSV/Parquet file on first run, so
    subsequent runs load instantly without re-translating.
  - For French topic, ALL English articles are translated (the translation
    cache is keyed on article ID to avoid duplicates).
  - For French sentiment, the cached translated corpus is expected to be
    pre-generated and stored as a Parquet file in translated_data/.

Trade-offs of machine translation:
  - MT introduces noise (awkward phrasing, occasional mis-translation).
  - However, CamemBERT-large is robust to imperfect French because its
    pre-training corpus itself contains diverse registers and some noise.
  - In preliminary experiments, training on mixed real + MT data consistently
    outperformed training on real data only (5–7% absolute F1 gain for topic).

────────────────────────────────────────────────────────────────────────────────
5. LAYERWISE LEARNING RATE DECAY (LLRD)  — Arabic Topic Only
────────────────────────────────────────────────────────────────────────────────

A well-known finding (Sun et al., 2019; Howard & Ruder ULMFiT) is that lower
Transformer layers encode generic syntactic features that should change slowly,
while upper layers encode task-specific semantics that should adapt quickly.

We apply LLRD with a decay factor of 0.95 per layer:
  - Classification head: LR = 1e-5  (full speed)
  - Layer 11 (top):      LR = 1e-5 × 0.95^1
  - Layer 10:            LR = 1e-5 × 0.95^2
  - …
  - Embeddings:          LR = 1e-5 × 0.95^12  (almost frozen)

This consistently prevented catastrophic forgetting of Arabic morphology in our
early experiments where a uniform LR caused a sharp drop in validation F1 after
the first epoch.

Why only Arabic topic?
  Arabic morphology is exceptionally complex; lower Transformer layers encode
  root-pattern morphology that is hard to relearn. English and French models
  are fine-tuned with uniform LR because their morphology is simpler and the
  standard warmup-then-decay cosine schedule is sufficient.

────────────────────────────────────────────────────────────────────────────────
6. TEXT AUGMENTATION — ENGLISH SENTIMENT
────────────────────────────────────────────────────────────────────────────────

English sentiment training uses a TextAugmenter class applying three techniques
during the training data loader (live augmentation, not pre-generated):

  a) Synonym replacement (15% per word)
     Sentiment-preserving synonyms from a curated dictionary
     (good→great, bad→terrible, love→adore, …).

  b) Random word deletion (keep_prob=0.85)
     Simulates incomplete or telegraphic news sentences.

  c) Random adjacent word swap (1 swap per augmentation)
     Forces the model to rely on semantic content rather than word order.

These augmentations are applied with AUGMENT_PROB=0.3 (30% chance per sample
per training step) and up to MAX_AUGMENTATIONS=2 techniques stacked.
Validation and test sets are never augmented.

Why not back-translation for English?
  Back-translation (EN→FR→EN) is higher quality but adds significant runtime
  overhead and a dependency on a translation model. The simpler techniques
  above gave sufficient regularization without the added complexity.

────────────────────────────────────────────────────────────────────────────────
7. HYPERPARAMETER CHOICES — THE STORY BEHIND THE NUMBERS
────────────────────────────────────────────────────────────────────────────────

  MAX_LEN
  ───────
  Arabic sentiment:  512 (with sliding window for documents > 512 tokens)
  Arabic topic:      512 (full body needed for topic determination)
  English sentiment: 160 (Twitter-style headlines rarely exceed this length)
  English topic:     512 (topic sometimes only becomes clear in the body)
  French sentiment:  384 (balances coverage vs. VRAM on RTX 3050 + large model)
  French topic:      512 (single-pass truncation; no sliding window)

  Batch Size & Gradient Accumulation
  ───────────────────────────────────
  Our hardware is an RTX 3050 with 4–6 GB VRAM (laptop). Fitting large models
  at MAX_LEN=512 with fp16 limits physical batch to 2–8 samples. Gradient
  accumulation simulates a larger effective batch:

    Arabic sentiment:  BATCH=4,  GRAD_ACCUM=4  → effective batch = 16
    Arabic topic:      BATCH=8,  GRAD_ACCUM=4  → effective batch = 32
    English sentiment: BATCH=8,  GRAD_ACCUM=4  → effective batch = 32
    English topic:     BATCH=8,  GRAD_ACCUM=4  → effective batch = 32
    French sentiment:  BATCH=4,  GRAD_ACCUM=8  → effective batch = 32
    French topic:      BATCH=4,  GRAD_ACCUM=4  → effective batch = 16

  Learning Rate
  ─────────────
  Arabic sentiment:  1e-5 (cosine-with-restarts; warm-started from sentiment ckpt)
  Arabic topic:      1e-5 (with LLRD — head sees full 1e-5, embeddings ~5.4e-7)
  English sentiment: 5e-6 (lower for large model stability)
  English topic:     1e-5 (standard BERT fine-tuning recommendation)
  French sentiment:  1e-5 (cosine)
  French topic:      5e-6 (halved for final fine-tune "cooling down" phase)

  Warmup
  ──────
  A warmup phase prevents gradient explosions at the start of training when
  the randomly initialised classification head produces large gradients.
  WARMUP_RATIO=0.1–0.2 is applied universally; Arabic sentiment additionally
  uses WARMUP_STEPS=1000 as a hard floor.

  Early Stopping
  ──────────────
  Patience is chosen conservatively for topic models (10–20 evaluation
  intervals) because macro F1 on 18 imbalanced classes can plateau for many
  evaluations before improving. Sentiment models use shorter patience (5–10)
  because convergence is faster and cleaner.

────────────────────────────────────────────────────────────────────────────────
8. TRAINING STABILITY — fp16, GRADIENT CHECKPOINTING, AUTO-RESUME, OOM GUARD
────────────────────────────────────────────────────────────────────────────────

  Mixed Precision (fp16 / bf16 / tf32)
  ─────────────────────────────────────
  Using fp16 halves VRAM consumption and speeds up matrix multiplications on
  Ampere GPUs (RTX 3050). We also enable tf32 matmul precision for an
  additional ~10% throughput improvement at no accuracy cost. French models
  use bf16 automatically when supported (Ampere+), falling back to fp16.

  Gradient Checkpointing
  ──────────────────────
  Trades compute for memory: intermediate activations are recomputed during
  the backward pass instead of stored. Enabled for Arabic sentiment (saves
  ~30% VRAM at ~20% compute overhead). Deliberately DISABLED for French
  CamemBERT-large because the compute overhead on our GPU is prohibitive
  for the 435M-parameter model — VRAM is managed instead via small batch size.

  Auto-Resume from Latest Valid Checkpoint
  ────────────────────────────────────────
  All six scripts include a checkpoint-scanner that:
    1. Searches the experiment output directory for all checkpoint-XXXX folders.
    2. Validates each checkpoint by checking for trainer_state.json AND
       model.safetensors (or pytorch_model.bin).
    3. Selects the checkpoint with the highest step number.
    4. Passes it to trainer.train(resume_from_checkpoint=...).
  This protects hours of GPU time against power cuts, OS updates, or
  deliberate interruptions.

  OOM Guard (English Sentiment)
  ─────────────────────────────
  The English sentiment script wraps trainer.train() in a retry loop (3
  attempts). On CUDA out-of-memory errors it halves the physical batch size
  and retries, allowing the job to complete even if initial memory estimates
  were too optimistic.

────────────────────────────────────────────────────────────────────────────────
9. EVALUATION PHILOSOPHY
────────────────────────────────────────────────────────────────────────────────

We never report only accuracy. On imbalanced datasets accuracy is a misleading
metric — a model predicting "Politics" for every article can achieve ~35%
accuracy while being completely useless.

Primary metric: Macro F1
  - Averages F1 equally across all classes, penalizing models that ignore
    rare categories. This is what report_search.py uses to rank runs.

Secondary metrics tracked per-run:
  - Per-class F1, precision, recall
  - Confusion matrix (CSV + PNG, counts and percentages)
  - Train/eval loss curves
  - Accuracy (for comparison with external benchmarks)
  - ROC curves + AUC per class (English sentiment, French topic)
  - Precision-Recall curves (English sentiment)
  - Per-class F1 bar chart — Validation vs. Test (English sentiment)
  - Prediction confidence distribution (English sentiment)
  - MSA vs. Dialect breakdown (Arabic sentiment)

Held-out test sets are fixed at the start of every run and never used for
model selection — only for the final reported numbers.

Data splits:
  - Arabic sentiment:  80% train / 10% validation / 10% test
                       Stratified independently for MSA and Dialect subsets.
  - Arabic topic:      80% train / 10% eval / 10% test (stratified)
  - English sentiment: 70% train / 15% validation / 15% test (stratified)
  - English topic:     80% train / 10% eval / 10% test (stratified)
  - French sentiment:  80% train / 10% validation / 10% test (stratified)
  - French topic:      80% train / 10% validation / 10% test (stratified)

────────────────────────────────────────────────────────────────────────────────
10. EXPERIMENT TRACKING & FOLDER CONVENTION
────────────────────────────────────────────────────────────────────────────────

Every run writes its outputs to a timestamped subfolder:

  experiments/
  ├── arabic_sentiment/   ← CAMeL-Lab BERT Mix Sentiment + Sliding Window
  ├── arabic_topic/       ← CAMeL-Lab BERT Mix + Focal Loss + LLRD
  ├── english_sentiment/  ← Twitter-RoBERTa-large + Text Aug + Auto-Resume
  ├── english_topic/      ← RoBERTa-Base + Focal Loss + Label Smoothing
  ├── french_sentiment/   ← CamemBERT-large + Focal + POSITIVE Augmentation
  └── french_topic/       ← CamemBERT-large + Translation + Class-Specific Gamma

Each run folder contains:
  best_model/             — exported weights & tokenizer
  checkpoints/            — periodic step snapshots
  hyperparameters.json    — immutable config snapshot at run start
  eval_results.json       — final macro F1, accuracy, per-class scores
  test_results.json       — held-out test set metrics
  predictions_<split>.csv — per-sample predictions with confidence scores
  summary.json            — comprehensive experiment report
  plots/                  — loss curves, F1 curves, confusion matrices,
                            ROC curves, AUC charts, confidence histograms

Use reports/report_search.py --task all to auto-rank all runs by macro F1.
